PIKOLBOOK FILE GUIDE - SIMPLE DEFENSE NOTES

The app uses 11 PHP files. Each page contains its form processing and HTML.
There are no controller, API, model, asset or framework folders.

index.php
  Checks email and password against users using password_verify().
  Starts the signed-in session, redirects to Dashboard, and handles logout.
  Loads script.js so the show/hide password button works. No sign-up page.

config.php
  Database settings and mysqli connection. Sets Philippine time for both
  PHP and MySQL. Holds merchant QR settings and query(), rows(), one().
  Prepared statements pass user values separately from SQL instructions.

functions.php
  Common login/role checks, form tokens, input validation, safe HTML output,
  dates and money. begin_write()/end_write() manage the lock and transaction.
  available() checks the full booking range against bookings and maintenance.
  repeat_dates() makes the weekly date list, stopping at month end.
  refund_quote() calculates the 100%, 50% or 0% refund using time until start.
  cancellation_targets() selects one booking or future dates in a block.
  net_received() subtracts recorded refunds from a paid booking's amount.
  calendar_slot() uses loaded bookings/maintenance to label each hourly cell.
  fail_form() restores safe booking entries after failure, excluding passwords.

layout.php
  Shared HTML functions:
  page_header() displays the menu and top bar for the signed-in user's role.
  page_footer() closes the page and displays confirmation/feedback dialogs.
  booking_modal() outputs the booking form and foreground error popup.
  cancellation_modal() outputs the cancellation review or refund form.
  booking_calendar() displays the month and selected day's court/time table.
  Keeping these together avoids extra PHP files for each popup.

bookings.php
  Checks POST actions and saves bookings, cancellations, completion or refunds.
  For a new monthly block it checks every date, verifies total payment, then
  creates all the bookings inside one transaction. A failure rolls back all.
  Client creation happens in the same transaction, so failed bookings do not
  leave a new client behind. Existing clients are selected from the database.
  Admin may reschedule future bookings; Staff cannot change their schedule.
  GET displays List/Calendar views, filters, booking records and action forms.

resources.php
  Court search/list and Admin create/edit/archive/delete forms.
  Admin sets maintenance start/end times; overlapping future reservations
  must be cancelled or rescheduled first. Staff has view-only access.

clients.php
  Client search/list, edit and delete. New clients are added during booking.
  Clients used by bookings are archived to preserve booking history.

staff.php
  Admin-only Staff search/list, creation, editing and deletion/deactivation.
  Phone is stored in users.phone. Editing details does not alter passwords.
  A separate password reset form requires the Admin's own current password.
  Staff referenced by bookings or refunds is deactivated instead of deleted.

profile.php
  Lets the current user edit their own name, email, phone and optional password.
  Requires their current password and matching new passwords if changing it.
  Uses the session's user ID, so a posted ID cannot edit somebody else.

reports.php
  Three report tabs: Periodic, per resource and per client.
  Only Periodic has month/year filters. Reports count individual booked dates.
  Net received subtracts actual recorded refunds; pending refunds remain visible.
  Data comes from MySQL and calculations use loops. No analytics service/API.

dashboard.php
  Today's schedule, bookings, courts in service, active clients and net receipts.
  Net receipts today subtracts refunds paid today from payments received today.
  Reuses the same New booking popup and saves through bookings.php.

style.css
  Your teammate's green theme, forms, icons, tables, popups and responsive styles.
  Adds ordinary CSS classes for the calendar and keeps sidebar font sizes and
  weights consistent. Printing hides navigation and prints the selected report.

script.js
  Handles popup buttons, password visibility, confirmation, client search,
  live table filters, report tabs, required fields, recurring date/price preview,
  calendar slot selection and print. Uses plain JavaScript and the existing DOM.
  No fetch calls, external API or database credentials are used in JavaScript.
  PHP validates the submitted values again; browser checks alone are not trusted.

pikolbook.sql
  Creates the database, tables, report views, missing courts and assigned accounts.
  Can be imported into an existing database without deleting booking/client data.
  Six tables:
    users           Admin/Staff accounts, hashed passwords, phone, role, status.
    clients         Customer name, email, phone and active status.
    courts          Court name, hourly rate, hours and active status.
    court_blocks    Maintenance periods. These are not paid monthly bookings.
    bookings        One reservation for one date, including its payment share.
    booking_details Optional monthly-block code and cancellation/refund history.
  booking_details uses booking_id to connect to bookings. It avoids adding
  repeated payment/refund text into booking notes or changing old records.
  Reimport preserves existing passwords, phones, bookings, clients and court rates.

img/logo.png and img/login_logo.png
  Original sidebar and login logos.
img/qrph.png (optional)
  The venue's real merchant QR image; provide it before using the QR display.

README.txt
  Installation, required SQL import, accounts, policy, workflows and limitations.
Week-1-Notes.txt and the two Week-1 PDFs
  Historical reference material. Current README/code take priority.

MONTHLY BLOCK EXAMPLE
1. Staff selects a client, Court 1, the month's first Tuesday, 5 PM and 2 hours.
2. repeat_dates() produces every Tuesday from that first date until month end.
3. PHP calls available() for every date and calculates hours x rate x dates.
4. PHP verifies the full payment and checks that its reference is not reused.
5. A loop inserts one booking per date, each with that date's payment share.
6. booking_details links the bookings with the same randomly generated code.
7. Commit saves the whole block. Any exception rolls back the entire submission.

CANCELLATION EXAMPLE
1. Open Cancel and choose one date or the block's future confirmed dates.
2. refund_quote() compares each start time with the current Philippine time.
3. The form shows each refund and the total before confirmation.
4. The server recalculates on submission. A changed amount requires a new review.
5. It marks bookings cancelled and stores refund_due, the reason and action user.
6. Staff sends the refund outside the app, then records its reference and amount.
7. Reports subtract refunded_amount only after that refund has been recorded.

OVERLAP RULE
Existing start < requested end AND existing end > requested start.
A 5-7 PM reservation blocks 6-8 PM, but allows 7-9 PM.
00:00 end time means midnight on the next date. Past and cancelled records are
handled separately: past slots cannot be booked; cancelled reservations free slots.

READING ORDER
index.php -> config.php -> functions.php -> layout.php -> bookings.php.
Then read staff.php/profile.php, resources.php, clients.php, reports.php,
dashboard.php and finally script.js/style.css for browser behavior and design.
